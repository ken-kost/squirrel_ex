# SquirrelEx

🐿️ **Type-safe SQL for Elixir.** Write plain `.sql` files; get typed Elixir
wrapper modules generated for you by introspecting PostgreSQL — on every
`mix compile`.

This is an Elixir port of the Gleam library
[squirrel](https://github.com/giacomocavalieri/squirrel). You keep writing real
SQL (so any SQL language server gives you autocomplete, schema-aware
suggestions, and linting), and squirrel_ex gives you a generated, committed,
IDE-readable `.ex` wrapper with a precise `@spec` next to each query.

## How it works

1. You write `.sql` files in `priv/sql/` — **one query per file**.
2. The `:squirrel_ex` Mix compiler runs on every `mix compile`.
3. It connects to PostgreSQL and, for each query, uses the extended-query
   *Parse/Describe* protocol (via `Postgrex.prepare/3`) to learn the query's
   **parameter types** and **result column names + types** — without executing
   it.
4. It maps the PostgreSQL type OIDs to Ecto types and Elixir typespecs
   (`int4 → integer()`, `text → String.t()`, `uuid → String.t()`, …).
5. It generates a typed wrapper module **next to** the `.sql` file
   (`priv/sql/list_posts.sql → priv/sql/list_posts.ex`). The generated file
   carries a `DO NOT EDIT` header and is meant to be committed to source
   control.

Generation is incremental: a query is only re-introspected when its `.sql`
content changes, and deleting a `.sql` removes its generated `.ex`.

### Example

`priv/sql/list_posts.sql`:

```sql
-- List a post's id, title and (nullable) body by author.
select id, title, body? from posts where author_id = $1 order by title
```

generates `priv/sql/list_posts.ex`:

```elixir
# This file was generated by squirrel_ex from priv/sql/list_posts.sql. DO NOT EDIT.
defmodule MyApp.Sql.ListPosts do
  @moduledoc """
  List a post's id, title and (nullable) body by author.

  Generated from `priv/sql/list_posts.sql`.
  """

  @sql ~S"""
  -- List a post's id, title and (nullable) body by author.
  select id, title, body from posts where author_id = $1 order by title
  """

  @type row :: %{id: String.t(), title: String.t(), body: String.t() | nil}

  @spec run(repo :: Ecto.Repo.t(), author_id :: integer()) ::
          {:ok, [row()]} | {:error, term()}
  def run(repo, author_id) do
    case Ecto.Adapters.SQL.query(repo, @sql, [author_id]) do
      {:ok, %{columns: cols, rows: rows}} ->
        keys = Enum.map(cols, &String.to_atom/1)
        {:ok, Enum.map(rows, fn row -> keys |> Enum.zip(row) |> Map.new() end)}

      {:error, _} = error ->
        error
    end
  end
end
```

Call it with your repo:

```elixir
{:ok, posts} = MyApp.Sql.ListPosts.run(MyApp.Repo, author_id)
# => [%{id: "…", title: "Hello", body: nil}, …]
```

## Installation

Add `:squirrel_ex` to your deps:

```elixir
def deps do
  [
    {:squirrel_ex, "~> 0.1"}
    # :ecto_sql and :postgrex are required (you almost certainly already have them)
  ]
end
```

## Host-application setup

Two things in your `mix.exs` `project/0`:

```elixir
def project do
  [
    # ...
    # Run the squirrel_ex compiler BEFORE :elixir so generated modules exist
    # when the Elixir compiler runs.
    compilers: [:squirrel_ex] ++ Mix.compilers(),

    # Elixir only compiles files under elixirc_paths. Add your SQL directory
    # so the generated .ex modules get compiled.
    elixirc_paths: ["lib", "priv/sql"]
  ]
end
```

> If you forget to add `priv/sql` to `elixirc_paths`, squirrel_ex emits a
> warning during compilation.

Then tell squirrel_ex how to reach your **development** database (only used at
compile time, to introspect queries) and which namespace/repo to generate for:

```elixir
# config/dev.exs
config :squirrel_ex,
  otp_app: :my_app,        # derive the DB connection from MyApp.Repo's config
  namespace: "MyApp.Sql",  # generated modules live under this namespace
  repo: MyApp.Repo         # the repo the generated run/N calls at runtime
```

### Configuration

All keys live under `config :squirrel_ex`:

| Key | Default | Description |
| --- | --- | --- |
| `:connection` | — | A `Postgrex.start_link/1` keyword list (`hostname`, `port`, `username`, `password`, `database`). Highest priority. |
| `:otp_app` | — | When `:connection` is absent, derive the connection from this app's Ecto `:repo` config. |
| `:repo` | `<CamelizedOtpApp>.Repo` | The `Ecto.Repo` the generated `run/N` calls at runtime. |
| `:namespace` | `<CamelizedOtpApp>.Sql` | Output module namespace. |
| `:sql_paths` | `["priv/sql/**/*.sql"]` | Globs to search for `.sql` files. |
| `:default_nullable` | `false` | Whether unannotated result columns are nullable. |

If neither `:connection` nor a usable repo config is found, squirrel_ex falls
back to `DATABASE_URL`, or the standard `PGHOST` / `PGPORT` / `PGUSER` /
`PGPASSWORD` / `PGDATABASE` environment variables.

## Nullability annotations

The database describe step does not report column nullability, so by default
every result column is typed as non-`nil`. You override per column with a suffix
on the **output column name** (the suffix is stripped from the SQL that is
actually run):

- `body?` → the column is nullable (`String.t() | nil`)
- `email!` → force the column non-nullable

```sql
select id, title, body? from posts
```

Set `config :squirrel_ex, default_nullable: true` to flip the default so columns
are nullable unless annotated with `!`.

## Parameter names

squirrel_ex infers friendly parameter names from the SQL around each `$n`
placeholder (e.g. `where author_id = $1` → `author_id`). Recognised shapes:
`col = $n`, `$n = col`, `table.col = $n`, comparison/`LIKE` operators, and
`col IN ($n)`. When nothing matches, parameters fall back to `arg1`, `arg2`, …

## Type mapping

| PostgreSQL | Ecto type | Elixir typespec |
| --- | --- | --- |
| `bool` | `:boolean` | `boolean()` |
| `int2` / `int4` / `int8` | `:integer` | `integer()` |
| `float4` / `float8` | `:float` | `float()` |
| `numeric` | `:decimal` | `Decimal.t()` |
| `text` / `varchar` / `bpchar` / `char` / `name` | `:string` | `String.t()` |
| `uuid` | `Ecto.UUID` | `String.t()` |
| `bytea` | `:binary` | `binary()` |
| `json` / `jsonb` | `:map` | `map()` |
| `date` | `:date` | `Date.t()` |
| `time` | `:time` | `Time.t()` |
| `timestamp` | `:naive_datetime` | `NaiveDateTime.t()` |
| `timestamptz` | `:utc_datetime` | `DateTime.t()` |

Unknown OIDs are resolved at compile time with a `pg_type` lookup: enums map to
`String.t()`; anything else falls back to a permissive `term()` with a warning.

## Limitations (v1)

- **Nullability** is annotation-driven (`?` / `!`) with a configurable default;
  there is no join-plan (`EXPLAIN`) analysis yet, so columns from `LEFT JOIN`s
  are not automatically detected as nullable.
- Result rows are returned as plain maps with atom keys (no per-query struct).
- One query per `.sql` file.
- Requires PostgreSQL (introspection uses the Postgres wire protocol).

## Development

Tests need a local PostgreSQL. The DB-backed suite connects as
`postgres`/`postgres` to `localhost:5432` (override with the `PG*` env vars) and
uses a database named `squirrel_ex_test`:

```sh
createdb -h localhost -U postgres squirrel_ex_test   # once
mix deps.get
mix test                 # runs unit + :db tests (skips :db if PG is unreachable)
mix test --exclude db    # unit tests only, no database needed
```
